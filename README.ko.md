# steadycheck

**메모리 오류가 "났다"가 아니라 "어디서 났는지"까지 알려 주는 윈도우용 무료 CPU·메모리 안정성 검사기.** 설치 없이 exe 하나, 결과는 PASS 아니면 FAIL.

게임이 튕기거나 블루스크린이 뜰 때, 램 오버클럭이나 XMP/EXPO 를 바꾼 뒤, 또는 PC 를 내보내기 전 마지막 검사로 쓰세요.

[최신 버전 받기](https://github.com/kimjione1206/steadycheck/releases/latest) · [시험하는 법과 결과 읽기](docs/TESTING.ko.md) · [English](README.md)

- **모든 비트를 정답과 대조.** 모든 CPU 코어가 같은 계산을 해 정답과 비교하고, 메모리는 써 넣은 값을 다시 읽어 한 비트까지 비교합니다. 한 비트라도 틀리면 FAIL 입니다.
- **메모리 오류가 어디서 났는지 알려 줍니다.** 틀린 값이 메모리에 *저장된* 것인지, *읽어 오는 과정*에서 틀린 것인지, 그리고 64바이트 캐시 줄의 512개 비트 중 몇 번째가 틀렸는지 알려 줍니다. 칸(셀) 불량인지, 데이터선 문제인지, 설정이 너무 빡빡한지 짐작하는 단서가 됩니다.
- **검사기 자체를 검사했습니다.** 고장 난 메모리를 흉내 낸 시뮬레이터, 실행 중에 바깥에서 비트를 뒤집어 넣기, 일부러 망가뜨린 자기 코드로 메모리 검사를 확인했습니다([아래](#어디까지-확인했나) 참고).

> **초기 버전 — 함께 시험해 주실 분을 찾습니다.** 흉내 고장, 바깥에서 비트 뒤집기, 일부러 망가뜨린 코드로 확인했지만 **실제 불안정·불량 PC 에서는 아직 확인하지 못했습니다.** 불안정한 줄 아는 설정이 있다면 10분 정도면 됩니다: [돕는 방법](#실제-pc-로-시험-돕기).

## 돌리기 전에

- **창 화면 없음:** 터미널에 명령 한 줄을 입력해 돌립니다(아래에 있음).
- **서명 없는 exe:** 윈도우 SmartScreen 이 "알 수 없는 게시자" 경고를 띄울 수 있습니다. 윈도우 11 **스마트 앱 컨트롤**이 켜져 있으면 서명 없는 프로그램은 막혀 아예 실행할 수 없습니다.
- **높은 부하:** CPU 와 메모리를 끝까지 돌려 열과 소음이 크고, 불안정한 PC 는 멈추거나 다시 켜질 수 있습니다. 작업은 저장하고, 일부러 불안정하게 맞춘 설정에서는 중요한 파일을 백업하세요.

## 빠른 시작

1. [릴리스](https://github.com/kimjione1206/steadycheck/releases/latest)에서 `steadycheck-<버전>-windows-x86_64.exe` 를 받습니다.
2. 받은 폴더의 빈 곳을 마우스 오른쪽 단추로 누르고 **터미널에서 열기**를 고릅니다(윈도우 10: Shift + 오른쪽 클릭 → **여기에 PowerShell 창 열기**).
3. 다른 프로그램을 닫고 아래 중 하나를 실행합니다(받은 버전으로 — `.\steadycheck` 까지 치고 **Tab** 을 누르면 파일 이름이 채워집니다).

PC 전체 검사 — CPU, 코어끼리 주고받기, 메모리(약 15분):

    .\steadycheck-0.6.0-windows-x86_64.exe all --mb auto --seconds 300 > result.json

불안정이 의심되는 메모리 설정 검사, 오류 20개까지 기록(약 10분):

    .\steadycheck-0.6.0-windows-x86_64.exe mem --mb auto --seconds 600 --require-complete --keep-going 20 > result.json

출고 검사처럼 짧게 돌린 것을 합격으로 착각하면 안 될 때는 `--require-complete` 를 붙이세요. 덜 된 검사는 PASS 대신 INCOMPLETE 로 끝납니다.

창의 마지막 줄에 `판정: PASS`, `판정: FAIL`, `판정: INCOMPLETE` 중 하나가 나옵니다. 전체 결과는 `result.json` 에 있습니다.

## 결과 읽기

| 판정 | 종료 코드 | 뜻 | 할 일 |
|---|---|---|---|
| PASS | 0 | 이번 실행에서는 틀린 값을 못 찾았습니다. | 보증은 아닙니다. 메모리는 충분히 오래 돌았어야 합니다: `mem.rounds_d`(끝낸 무작위 메모리 회차 수)가 4 이상이어야 하고, 아니면 더 오래 돌리거나 `--require-complete` 를 붙여 자동으로 확인하게 하세요. |
| FAIL | 1 | 틀린 값을 잡았습니다 — 또는 검사 일부가 아예 돌지 못했습니다(`error` 항목을 보세요. `error` 가 없는데 `min_thread_…` 값이 0 이면 검사 일부가 아예 돌지 못한 것으로, 대개 PC 가 바빴던 때문입니다). | 오버클럭이나 XMP/EXPO 를 낮추거나, 메모리를 한 개씩 꽂아 다시 시험하세요. 오류의 `kind` 가 `panic` 이면 steadycheck 의 버그이니 알려 주세요. |
| INCOMPLETE | 4 | 오류는 없지만 메모리 검사가 덜 됐습니다(`--require-complete` 일 때만). | `--seconds` 를 늘려 다시 돌리세요. |

종료 코드 2 는 이 PC 가 요청한 기능을 지원하지 않음(또는 메모리 크기를 읽지 못함), 3 은 명령을 잘못 친 것 같은 사용법 오류입니다.

메모리 오류는 이렇게 보입니다(일부러 비트 하나를 뒤집는 `steadycheck mem --mb 64 --seconds 10 --inject-mem 1:500` 의 출력 일부):

```json
{
  "injected": true,
  "verdict": "FAIL",
  "mem": {
    "error": {
      "thread": 0,
      "pass": 1,
      "stage": "B",
      "element": 1,
      "pattern": "solid",
      "offset_bytes": 4000,
      "expected": "0x0000000000000000",
      "actual": "0x0000000000000001",
      "reread": "0x0000000000000001",
      "kind": "stored",
      "line_bits": [256]
    }
  }
}
```

- `kind: "stored"`: 메모리에서 곧바로 다시 읽어도 틀린 값이 나와, 틀린 값이 메모리에 들어 있다는 뜻입니다. `kind: "read"` 라면 메모리에는 맞는 값이 있고 읽어 오는 과정에서 틀린 것입니다.
- `line_bits`: 64바이트 줄 안에서 틀린 비트의 자리(0~511). 서로 다른 주소에서 같은 자리가 틀리면 데이터선, 같은 주소가 또 틀리면 칸(셀), 자리가 흩어지면 신호 품질이나 너무 빡빡한 설정을 의심할 수 있습니다. 검사 자체는 DDR3·DDR4·DDR5 모두 같습니다. 다만 메모리 채널이 둘 이상이면(DDR4 도) 같은 자리라도 다른 채널일 수 있고, DDR5 는 모듈의 하위 채널 두 개 중 어느 쪽일 수도 있어 다른 핀일 수 있으니 "데이터선" 은 단서로만 보세요([메모리 종류별로 읽는 법](docs/HOW-IT-WORKS.md), 영어).
- `--keep-going N` 이면 메모리 검사가 첫 오류에서 멈추지 않습니다. `mem.errors_total` 과 `mem.errors` 목록으로 오류를 몇 개, 언제 잡았는지 볼 수 있습니다.
- 윈도우에서는 검사하는 동안 남은 윈도우 하드웨어 오류 기록(WHEA) 수(`whea`)와 PC 전체 메모리 중 검사한 비율(`mem.tested_percent`)도 함께 나옵니다. 둘 다 판정은 바꾸지 않습니다.

## 무엇을 검사하나

| 모드 | 하는 일 |
|---|---|
| `cpu` | 모든 논리 CPU 가 같은 정수·부동소수점(FMA)·압축 해제 모양 계산을 하고(가능하면 AVX2/AVX-512 사용), 결과가 정답과 정확히 같아야 합니다. |
| `share` | 코어끼리 메시지를 주고받고 공용 숫자에 더합니다. 모든 메시지와 최종 합이 정확해야 합니다. |
| `mem` | 메모리에 정해진 무늬를 써 넣고 다시 읽습니다. 메모리 검사의 표준 순서(March C-), 캐시 줄 줄무늬 9종, 무작위 반복, 빠른 읽기/쓰기 전환을 씁니다. |
| `all` | `cpu` → `share` → `mem` 을 각각 `--seconds` 동안. 첫 실패에서 멈춥니다. |

단계·옵션·출력 항목 전체 설명은 [How it works](docs/HOW-IT-WORKS.md)(영어)에 있습니다.

## 어디까지 확인했나

- **고장 흉내 메모리:** 실제 메모리 검사 코드를 고장 하나를 넣은 작은 흉내 메모리에서 돌립니다. 기본 세트는 일꾼 하나이거나 일꾼 속도가 같으면 그 목록의 고장(고착 비트, 바뀌지 않는 비트, 주소 고장, 칸끼리 간섭, 데이터선 단락)을 전부 잡습니다. 일꾼 속도가 다를 때 놓칠 수 있는 칸끼리 간섭은 시험한 속도 비율 모두에서 무작위 회차 4번 뒤 전부 잡혔으니 `mem.rounds_d` 가 4 이상인지 보세요. 시뮬레이터 안 목록 기준이며, 실제 불량 전부를 약속하지는 않습니다([검출표와 한계](docs/HOW-IT-WORKS.md)).
- **바깥에서 고장 넣기:** 다른 프로그램이 실행 중인 steadycheck 의 메모리 비트를 고정하거나 뒤집습니다. 고정된 비트는 잡고 주소와 비트를 맞게 알려 줍니다(잠깐 뒤집힌 비트는 다시 읽기 전에 덮여 못 잡을 때가 있습니다).
- **변이 시험:** 메모리 검사·시뮬레이터·판정·명령줄·윈도우 기록 코드를 일부러 수백 가지로 조금씩 망가뜨려 시험이 알아채는지 봅니다. 최근 결과(전체 실행 한 번 + 시험을 보탠 줄의 변이만 다시 돌린 결과)에서 망가뜨린 807개 중 756개를 잡았고(그중 3개는 시험이 이미 실패한 뒤 시간 제한에 걸린 것), 26개는 빌드되지 않았으며, 25개는 바뀐 것이 겉으로 드러나지 않아 잡을 수 없음을 보였습니다(같은 뜻 22, 관찰할 수 없는 메모리 울타리(fence) 1, 시간만 바뀜 2). 잡을 수 있는 것은 전부 잡았습니다([전체 목록](docs/MUTATION-RESULTS.md), 영어). CPU·코어 주고받기 코드는 대상이 아닙니다.
- **아직 못 한 것:** 실제 불안정·불량 하드웨어.

**한계.** DDR5 는 칩 안에서 비트 하나짜리 오류를 알리지 않고 고치므로(on-die ECC) 어떤 소프트웨어 검사로도 보이지 않습니다. RowHammer 는 범위 밖입니다. 윈도우 안에서 돌기 때문에 윈도우와 다른 프로그램이 쓰는 메모리는 검사하지 못합니다. PASS 는 보증이 아닙니다.

## 받은 파일 확인

[릴리스](https://github.com/kimjione1206/steadycheck/releases/latest)에서 exe 와 `SHA256SUMS.txt` 를 받습니다. 둘 다 이 저장소에서 GitHub Actions 가 만듭니다. 코드 서명이 없으므로 아래 확인으로 진짜 파일인지 알 수 있습니다.

<details>
<summary>진짜 파일인지 확인하기</summary>

- 지문: 받은 폴더의 PowerShell 에서 아래 한 줄이 `True` 를 찍으면 `SHA256SUMS.txt` 와 같은 파일입니다:
  `(Get-FileHash .\steadycheck-<버전>-windows-x86_64.exe -Algorithm SHA256).Hash -eq (-split (Get-Content .\SHA256SUMS.txt))[0]`
- 선택 — 만든 곳: `gh attestation verify steadycheck-<버전>-windows-x86_64.exe -R kimjione1206/steadycheck --source-ref refs/tags/v<버전> --signer-workflow kimjione1206/steadycheck/.github/workflows/release.yml` (GitHub CLI 와 `gh auth login` 필요). 그 릴리스 태그에서 만든 파일일 때만 통과합니다.

</details>

## 실제 PC 로 시험 돕기

지금까지는 흉내 고장, 바깥 주입, 변이 시험으로만 확인했고 실제 불안정·불량 PC 에서는 아직입니다.
불안정한 줄 아는 설정, 확실히 안정적인 PC, 또는 불량이 확인된 부품으로 돌려 줄 수 있다면 [시험 안내서](docs/TESTING.ko.md)를 보세요.
주의 사항, 실행·결과 읽는 법, 어떤 제보 양식을 쓸지 적혀 있고, `tools/collect-info.ps1` 은 일련번호·사용자·컴퓨터 이름 없이 메모리 종류(DDR4·DDR5 등)를 포함한 하드웨어 정보를 모읍니다.
